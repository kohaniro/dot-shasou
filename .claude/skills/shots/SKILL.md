# 景色のスクリーンショット

描画を変えたら、このスクリプトで画像を出し、Read で開いて目で確かめる。依存なし（インストール済みの Chrome か Edge を使う。見つからなければ環境変数 `CHROME_PATH`）。確認用サーバーが止まっていれば自動で起動する。

```bash
node .claude/skills/shots/shots.mjs <出力フォルダ> <シード,シード> <絵柄,絵柄> [mode]
# 例: 2つのシード × 4つの絵柄で、景色だけの絵と車内込みの画面を保存
node .claude/skills/shots/shots.mjs "<scratchpad>/shots" 1234,7 real,soft,game,mono both
```

- **出力フォルダ**はプロジェクトの外（セッションの scratchpad）にする。省略すると OS の一時フォルダの `dot-shasou-shots`。
- **絵柄**: `real` / `soft` / `game` / `mono`
- **mode**（省略時 `both`）

| mode | 出すもの | ファイル名 |
|---|---|---|
| `raw` | 車内を重ねない景色だけの絵（幅480ドット、2倍） | `raw-<シード>-<絵柄>-a.png` / `-b.png` |
| `view` | 車内・乗客込みの実際の画面 | `view-<シード>-<絵柄>-a.png` / `-b.png` |
| `both` | 上の両方 | |
| `run` | 実際のループを150秒ぶん進め、30秒ごとの画面を1枚に並べる | `run-<シード>-<絵柄>.png` |
| `pano:<距離,距離>` | 指定した走行距離の、横1280ドットの絵（チャンクの継ぎ目の確認） | `pano-<シード>-<絵柄>.png` |
| `at:<距離,距離>` | 指定した走行距離（`state.dist`。窓の中央の地点は +160）の、車内・乗客込みの実際の画面を縦に並べる（坑口の手前・直後など、任意の地点の確認） | `at-<シード>-<絵柄>.png` |
| `zoom:<距離,距離>` | 指定した走行距離の4倍拡大 | `zoom-<シード>-<絵柄>.png` |
| `perf` | レイヤーごとのチャンク生成時間を表示（画像なし） | |
| `station` / `station:<k,k>` | 駅 k（省略時 1,2）ごとに、車内込みの画面を「進入中（残り約600ドット・減速中）」「停車・ドア全開」「発車直後（pos+300 付近、ドア閉）」の3コマ縦に並べる。同じ3地点の景色だけの絵（幅480・2倍）も出す。駅名・pos・規模・ホーム範囲と各コマの進行状態を表示 | `station-<シード>-<絵柄>-k<k>.png` / `station-raw-<シード>-<絵柄>-k<k>.png` |
| `door` / `door:<k,k>` | 駅 k（省略時 1,2）に停車し、ドアが開く途中（開き始め・半開き・ほぼ全開）の車内込みの画面を3コマ縦に並べる | `door-<シード>-<絵柄>-k<k>.png` |
| `journey` / `journey:<秒>` | 実ループを 50ms 刻みで指定秒（既定420）進め、進行の状態の切り替わり（減速開始・停車・発車・巡航復帰）、停止位置の誤差、最大加減速度などを表示（画像なし） | |
| `pass` | 乗客の確認。絵柄ごとに1枚。渡したシードごとに、出発地点の車内込みの画面から座席まわり（内部座標 y=76〜150、幅320）を3倍に拡大して縦に並べ（表示は「あり」）、いちばん下に最初のシードを「シルエット」にした1コマを足す | `pass-<絵柄>.png` |
| `walk` | 歩く立ち姿（`drawWalker`）の確認。シードごとに1枚。出発地点の画面全体を3倍にした上に、7人（大人5・子ども1・高齢者1）を歩幅の違う瞬間で並べ、「右向き」「左向き」「右向きのシルエット」の3コマを縦に並べる | `walk-<シード>-<絵柄>.png` |
| `swap` / `swap:<k,k>` | 駅での乗客の入れ替え。駅 k（省略時 1,2）に停車し、車内込みの画面を「降りる人が立った直後」「降りる人が歩いている途中」「乗る人が入ってきたところ」「乗る人が歩いている途中」「全員が座ったあと（ドアが閉まる前）」「発車後」の6コマ縦に並べる。各コマの `stopT`、降りる人・乗る人の席番号、`dwell`、ずらす間隔と速さの倍率を表示。あわせて、区間3の顔ぶれが直接求めても順に求めても同じか、駅 1〜12 で全員が `tl.close` より前に座り終えるか（`margin`）も表示する | `swap-<シード>-<絵柄>-k<k>.png` |
| `feat` | トンネル・橋（`src/features.js`）の一覧。シードごとに d = 0〜260000 の区間（種類、通し番号 `#n`、種類ごとの番号 `k`、a、b、len、via、中心地点のバイオームの重みの上位2つ、直近の駅のホームまでの距離）と、種類ごとの個数、区間どうし・ホームとの最小間隔、`mount` / `sea` が 0.5 をまたぐ地点を表示（画像なし） | |
| `tunnel` / `tunnel:<k,k>` | k 番目（省略時 1,2）のトンネルごとに、車内込みの画面を「入口が窓の右寄り（画面 x=250 に a）」「入口が窓の中央」「区間の中ほど」「出口が窓の中央」の4コマ縦に並べる。同じ4地点の景色だけの絵（幅480・2倍）も出す。区間の a / b / len / via と各コマの dist、`featureMix` / `tunnelProx` の値を表示 | `tunnel-<シード>-<絵柄>-k<k>.png` / `tunnel-raw-<シード>-<絵柄>-k<k>.png` |
| `bridge` / `bridge:<k,k>` | 同じことを k 番目の橋で | `bridge-<シード>-<絵柄>-k<k>.png` / `bridge-raw-<シード>-<絵柄>-k<k>.png` |
| `course` | 線形（`src/course.js`）の一覧と検証。シードごとに d = 0〜200000 のカーブ（a、長さ、向きの変化、最もきつい所の `curve`、前のカーブとの間隔）と高架（a、b、勾配の長さ、中にある駅）、`heading` の範囲・傾きの最大、高架の割合、置いてはいけない場所（駅・橋・坑口・山間・海沿い）との重なりの有無を表示。あわせて描画なしで実際に走らせ、巡航中の加減速の最大、制限速度の超過、駅間ごとの最高速度（km/h）と制限速度の幅を表示（画像なし） | |
| `curve` / `curve:<k,k>` | k 番目（省略時 1,2）のカーブごとに、車内込みの画面を「始点 / 1/4 / 中ほど（最もきつい）/ 終点 が窓の中央」の4コマ縦に並べる。同じ地点の景色だけの絵も出す。各コマの `heading` / `curve` / `elev` / `lean` と速度を表示 | `curve-<シード>-<絵柄>-k<k>.png` / `curve-raw-<シード>-<絵柄>-k<k>.png` |
| `elev` / `elev:<k,k>` | 同じことを k 番目の高架で（上り勾配の始点 / 勾配の中ほど / 上りきった所 / 高架の中ほど / 下り勾配の中ほど） | `elev-<シード>-<絵柄>-k<k>.png` / `elev-raw-<シード>-<絵柄>-k<k>.png` |

`run` は 30 秒ごとの進行の状態（`dist` / `speed` / `phase` / `door`）も表示する。

`raw` / `view` は、「各バイオームの中心6点（a。最初に現れた区間。山間と海沿いは別の周になる）」と「遷移の境目5点（b。隣り合う組ごとに最初の1回）」を縦に並べた1枚にする（区切りはマゼンタの帯）。撮る地点の走行距離は実行時に表示されるので、`pano:` / `zoom:` の距離指定に使える。

景色だけの絵（`raw` / `pano:` / `zoom:` と各 mode の `-raw-`）は、高架の下げ幅（`Layer` の `drop` × `elev`）は反映するが、カーブの上下のずらし（カント）と揺れは反映しない。きついカーブの内側で窓の右端に出る前方の車両（`scenery/selftrain.js`。Layer ではなく `render()` が直接描く）も入らないので、車内込みの画面（`curve:` / `at:`）で見る。

## 出力の読み方

- `deterministic: YES` — 同じ条件で2回描いて同じ画像だった。`NO` なら生成コードに `Math.random()` や時刻への依存が紛れている。
- `Math.random calls` — 景色の生成中に呼ばれた回数。0 であること。
- `CONSOLE ERRORS: none` であること。

## 注意

- 時間と `Math.random` を差し替えた固定ステップでの確認なので、実ブラウザでの滑らかさや音は確かめられない。
- 画像を開くと枠を多く使う。まず `raw` を1シード・`real` で見て、問題なければ残りの絵柄を見る。全部を開く必要はない。
- バイオームを足したり `world.js` の公開名（`world` / `BIOME_KEYS`）や `state` の形を変えたりしたら、スクリプト内の `__plan` / `__goto` も合わせて直す。
- `__goto(距離, stopT)` は `journey.js` の `seekJourney()` で進行の状態（`phase` / `station` / `door`）もその地点に合わせて置き直す。駅の `pos` ちょうどに飛ぶと停車中（`stopT` 秒後）になる。`view` の地点が駅の前後（減速・加速中）に当たると、2フレーム進む距離が巡航時と変わるので、駅を入れる前の画像とはハッシュが一致しない。
